# FunPay Auto-Bot

Бот для подготовки и публикации цифровых товаров на FunPay. Он:

- берёт игры из `data/games_list.txt`;
- находит раздел игры на FunPay;
- генерирует идеи и подробные гайды через личный Cloudflare Worker;
- загружает гайды на Google Drive;
- создаёт и публикует лоты;
- ведёт логи, тайминги и расход токенов;
- подстраивает три обязательных товара под конкретную игру.

Текущая версия инструкции: **v19.5**.

> Важно: бот не запускает Zapret, WARP, `winws`, `warp-cli`, системные маршруты и команды от администратора. FunPay открывается напрямую, а при необходимости используется обычный прокси из `.env`.

## 1. Быстрый запуск

### Что нужно подготовить

- Windows;
- Python 3.10 или новее;
- аккаунт FunPay и Golden Key;
- Google Drive и OAuth Desktop app для Google Drive API;
- аккаунт Cloudflare;
- интернет, с которого открывается FunPay и адрес Worker'а.

### Команды PowerShell

Открой PowerShell и выполни команды из папки проекта:

```powershell
cd C:\путь\к\rublyevky
py -m pip install -r requirements.txt
Copy-Item .env.example .env
```

После этого заполни `.env`, настрой Google Drive и Cloudflare Worker по разделам ниже.

Сначала всегда запускай безопасную проверку:

```powershell
py main.py --selftest
```

`--selftest` ничего не публикует и не обрабатывает игры. Когда все обязательные пункты готовы, запускай бота:

```powershell
py main.py
```

Остановить работу можно сочетанием `Ctrl + C`.

## 2. Файл `.env`

Файл должен лежать рядом с `main.py` и называться именно `.env`, а не `.env.txt`.

Минимальная настройка:

```dotenv
GOLDEN_KEY=твой_golden_key_от_funpay
GOOGLE_DRIVE_FOLDER_ID=id_папки_google_drive
AI_WORKER_URL=https://имя-твоего-worker.workers.dev
AI_WORKER_TOKEN=секретный_пароль_worker
AI_MODEL_PRIORITY=@cf/qwen/qwen3-30b-a3b-fp8,@cf/openai/gpt-oss-120b,@cf/openai/gpt-oss-20b
AI_TIMEOUT=180
```

### Что означает каждая строка

| Переменная | Обязательно | Назначение |
|---|---:|---|
| `GOLDEN_KEY` | да | Авторизация на FunPay. Берётся в настройках FunPay. |
| `GOOGLE_DRIVE_FOLDER_ID` | да | ID папки, куда бот загружает гайды. |
| `AI_WORKER_URL` | да | Адрес личного Cloudflare Worker без завершающего `/`. |
| `AI_WORKER_TOKEN` | да | Должен совпадать с секретом `PROXY_TOKEN` на Worker'е. |
| `AI_MODEL_PRIORITY` | нет | Модели по порядку: слева направо, пока одна не ответит. |
| `AI_TIMEOUT` | нет | Таймаут одного запроса к ИИ в секундах. По умолчанию `180`. |
| `AI_ATTEMPTS` | нет | Число попыток одной модели. По умолчанию `2`. |
| `PROXY_URL` | нет | Обычный HTTP-прокси только если FunPay или Worker не открываются напрямую. |

Основной порядок моделей уже выбран безопасно для лимитов:

```dotenv
AI_MODEL_PRIORITY=@cf/qwen/qwen3-30b-a3b-fp8,@cf/openai/gpt-oss-120b,@cf/openai/gpt-oss-20b
```

Если на Worker добавлен Gemini, его можно поставить последним запасным вариантом:

```dotenv
AI_MODEL_PRIORITY=@cf/qwen/qwen3-30b-a3b-fp8,@cf/openai/gpt-oss-120b,gemini-3.8-flash
```

Секреты нельзя вписывать в `README.md`, `worker/wrangler.toml` или другие файлы, которые отправляются в Git. Файлы `.env`, `token.json`, `client_secrets.json` и локальные секреты Wrangler уже исключены через `.gitignore`.

## 3. Google Drive через OAuth Desktop app

Сервисный аккаунт для обычной настройки не нужен. Используй OAuth-клиент типа **Desktop app**.

### Подготовка Google Cloud

1. Открой [Google Cloud Console](https://console.cloud.google.com/).
2. Создай проект или выбери существующий.
3. Включи **Google Drive API**: `APIs & Services` → `Library` → `Google Drive API` → `Enable`.
4. Открой `APIs & Services` → `Credentials`.
5. Создай **OAuth client ID**.
6. В качестве типа приложения выбери **Desktop app**.
7. Скачай JSON-файл.
8. Переименуй его в `client_secrets.json` и положи рядом с `main.py`.
9. Если Google попросит настроить экран согласия, добавь свой Google-аккаунт в Test users.

### ID папки

1. Создай папку на Google Drive.
2. Открой её в браузере.
3. Скопируй часть адреса после `/folders/`:

```text
https://drive.google.com/drive/folders/1abcDEF_example
                                         └──────────────┘
```

4. Впиши эту часть в `.env`:

```dotenv
GOOGLE_DRIVE_FOLDER_ID=1abcDEF_example
```

При первом запуске `py main.py --selftest` откроется браузер для разрешения доступа. После авторизации появится `token.json`. Не удаляй его и не добавляй в Git.

## 4. Cloudflare Worker для ИИ

Бот использует HTTP-клиент `modules/ai_client.py` и обращается только к своему Worker'у. Gemini SDK в боте не используется: если нужен Gemini, Worker обращается к нему сам через HTTP.

Схема:

```text
бот на Windows
    │ HTTPS + AI_WORKER_TOKEN
    ▼
твой Cloudflare Worker
    ├── Workers AI: @cf/qwen/... и @cf/openai/gpt-oss-...
    ├── Gemini по желанию
    ├── Groq по желанию
    └── OpenRouter по желанию
```

### Вариант A: через веб-панель Cloudflare

1. Открой [Cloudflare](https://dash.cloudflare.com/sign-up) и создай аккаунт.
2. Открой `Workers & Pages` → `Create` → `Create Worker`.
3. Создай Worker, например с именем `ai-worker`.
4. Нажми `Edit code`.
5. Удали демонстрационный код и вставь содержимое файла `worker/worker.js`.
6. Нажми `Deploy`.
7. В настройках Worker открой `Settings` → `Variables and Secrets`.
8. Добавь секрет:
   - имя: `PROXY_TOKEN`;
   - значение: длинный пароль, придуманный тобой.
9. В `Settings` → `Bindings` добавь **Workers AI** с именем привязки ровно `AI`.
10. Снова выполни `Deploy`.
11. Скопируй адрес Worker'а вида `https://имя.workers.dev` в `.env`:

```dotenv
AI_WORKER_URL=https://имя.workers.dev
AI_WORKER_TOKEN=тот_же_пароль_что_и_PROXY_TOKEN
```

### Вариант B: через Wrangler

Node.js для этого варианта должен быть установлен. Выполняй команды из PowerShell:

```powershell
cd C:\путь\к\rublyevky\worker
npx --yes wrangler login
npx --yes wrangler deploy
npx --yes wrangler secret put PROXY_TOKEN
```

Команда `secret put` попросит ввести значение скрытого секрета. Не вставляй его в чат, README или Git.

После добавления или изменения кода Worker его нужно повторно задеплоить:

```powershell
cd C:\путь\к\rublyevky\worker
npx --yes wrangler deploy
```

Локальные секреты Wrangler можно хранить в `worker/.dev.vars`; этот файл уже исключён из Git.

### Проверка Worker

Открой в браузере:

```text
https://имя.workers.dev/health
```

В рабочем ответе должно быть примерно следующее:

```json
{
  "ok": true,
  "version": "1.1",
  "colo": "...",
  "providers": {
    "cloudflare": true,
    "gemini": false,
    "groq": false,
    "openrouter": false
  }
}
```

- `ok: true` — Worker отвечает;
- `cloudflare: true` — подключена привязка Workers AI;
- `gemini: true` — на Worker задан `GEMINI_API_KEY`;
- `colo` — дата-центр, в котором обработан запрос.

После этого проверь всю цепочку с компьютера:

```powershell
cd C:\путь\к\rublyevky
py main.py --selftest
```

### Секрет Gemini и региональные ограничения

Если нужен Gemini как дополнительная модель, секрет добавляется на Worker, а не в `.env` бота:

```powershell
cd C:\путь\к\rublyevky\worker
npx --yes wrangler secret put GEMINI_API_KEY
npx --yes wrangler deploy
```

В текущем Worker поддерживаются следующие имена Gemini:

```text
gemini-3.8-flash
gemini-3.7-flash
gemini-3.6-flash
gemini-3.5-flash
gemini-3.5-flash-lite
gemini-3.1-flash-lite
```

Рекомендуемый пример с Gemini в конце цепочки:

```dotenv
AI_MODEL_PRIORITY=@cf/qwen/qwen3-30b-a3b-fp8,@cf/openai/gpt-oss-120b,gemini-3.8-flash
```

У Gemini могут быть ограничения по стране, аккаунту, бесплатной квоте и доступности конкретной модели. Даже если ключ создан, Google может вернуть ошибку региона или лимита. В таком случае бот не должен получать секреты: сначала используются модели, которые стоят левее в `AI_MODEL_PRIORITY`.

Бесплатные лимиты Cloudflare Workers AI также ограничены суточной квотой нейронов. Точная квота и стоимость могут меняться — проверяй их в панели Cloudflare. При ответе `429` бот переходит к следующей модели. Исключение `AILimitReached` появляется только после исчерпания всей цепочки моделей.

Запросы к Gemini могут использоваться Google для улучшения сервиса согласно настройкам аккаунта и тарифа. Не отправляй через Gemini ключи, пароли, персональные данные и содержимое `.env`.

### Другие запасные провайдеры

Worker также умеет работать с Groq и OpenRouter. Их ключи добавляются только как секреты Worker'а:

```powershell
cd C:\путь\к\rublyevky\worker
npx --yes wrangler secret put GROQ_API_KEY
npx --yes wrangler secret put OPENROUTER_API_KEY
npx --yes wrangler deploy
```

Модели этих провайдеров добавляй в `AI_MODEL_PRIORITY` только после проверки их доступности и лимитов.

## 5. Список игр и первый запуск

Список игр находится в:

```text
data/games_list.txt
```

Пиши по одной игре на строку:

```text
Cyberpunk 2077
Hogwarts Legacy
Valheim
```

Перед первым запуском сделай резервную копию списка:

```powershell
Copy-Item data\games_list.txt data\games_list_backup.txt
```

После успешной обработки бот удаляет игру из `data/games_list.txt` и переходит к следующей. Файл `data/processed_games.json` используется для защиты от повторной публикации и не должен редактироваться вручную.

### Самопроверка

```powershell
py main.py --selftest
```

Проверяются:

1. наличие `.env` и основных переменных;
2. доступность Worker и его `/health`;
3. тестовый ответ ИИ;
4. доступность FunPay и авторизация по `GOLDEN_KEY`;
5. Google Drive и возможность создать временную папку;
6. накопленный расход запросов и токенов за текущий день.

Самопроверка не публикует лоты и не удаляет игру из списка.

### Рабочий запуск

```powershell
py main.py
```

Для каждой игры бот:

1. находит категорию FunPay;
2. генерирует до 12 обычных идей;
3. проверяет три обязательных товара под игру;
4. получает ровно три обязательных товара — исходных или адаптированных;
5. создаёт до 15 гайдов;
6. загружает файлы в папку Google Drive;
7. публикует обычные лоты за 1 рубль;
8. при наличии игры в `data/wemod_games_list.txt` отдельно обрабатывает WeMod-лот за 60 рублей;
9. отмечает игру обработанной и удаляет её из входного списка.

## 6. Обязательные товары и адаптация под игру

Базовый список находится в `config.py` в переменной `MANDATORY_PRODUCTS`. У каждого товара есть устойчивый `id`:

- `pc_optimization`;
- `ping`;
- `hwid`.

Название, тип и `content_points` можно редактировать в `config.py`. Поля `id` не переименовывай: по ним сопоставляется ответ ИИ.

Проверка работает в два этапа:

1. быстрый локальный фильтр смотрит на название игры и раздел FunPay;
2. если ситуация неочевидна, один JSON-запрос ИИ оценивает все три товара сразу.

Для явно мобильной, консольной или офлайн-игры запрос к ИИ для очевидных замен не тратится. Неподходящие темы заменяются обычными игровыми идеями. Причина каждой замены попадает в:

```text
logs/mandatory_products.jsonl
```

В результате сохраняется схема:

```text
3 адаптированных обязательных товара + до 12 обычных идей = до 15 товаров
```

## 7. Тексты, summary и описания лотов

### Summary

Заголовок короткого описания укладывается одновременно в ограничения FunPay:

- от 10 до 70 символов;
- не больше 120 UTF-8 байт.

Сокращение выполняется осознанно:

1. убирается бонус;
2. убирается упоминание авто-выдачи;
3. сокращается название по целым словам;
4. только затем выбирается безопасный вариант из целых слов.

Посимвольного обрезания, разрыва слов и разрыва `U+FE0F` нет. Уровень сокращения пишется в лог.

### Полное описание

В полном русском описании явно остаётся одна строка `АВТОВЫДАЧА 24/7`. Текст вокруг неё варьируется: описания не состоят из одной копии с повторяющимися рекламными фразами.

### ИИ-гайды

Промпты требуют:

- конкретные игровые детали;
- обычные абзацы разной длины;
- редкие списки только там, где они полезны;
- отсутствие `##`, мета-вступлений, выводов и рядов декоративных эмодзи.

Перед проверкой качества бот удаляет запрещённые мета-фразы, финальные секции «Итоги»/«Выводы», Markdown-заголовки и подряд идущие эмодзи. Текст, в котором больше примерно 40% непустых строк являются пунктами списка, отбраковывается.

Если гайд оказался короче требуемого объёма, бот один раз просит дописать его. Текст длиннее 500 символов после дополнительной попытки может быть принят, если он не похож на отказ или список.

## 8. Ускорение и логи ИИ

Идеи начинают генерироваться параллельно с поиском раздела игры. При обработке товаров заранее готовится только следующий гайд; используется осторожный пул максимум из двух задач, поэтому бот не создаёт очередь из десятков запросов.

В консоли выводятся:

- время генерации идей;
- время генерации гайдов;
- время публикации;
- общее время обработки игры;
- количество запросов и токенов за игру.

Расход запросов сохраняется в:

```text
logs/ai_usage.jsonl
```

Причины ошибок пишутся в:

```text
logs/errors.log
```

Причины замен обязательных товаров пишутся в:

```text
logs/mandatory_products.jsonl
```

Логи не нужно добавлять в Git.

## 9. Сетевой слой и безопасность

Сетевой слой делает только следующее:

- создаёт обычную `requests.Session`;
- проверяет доступность FunPay;
- использует `PROXY_URL`, если он задан;
- пересоздаёт сессию при сетевом обрыве.

Он не делает следующего:

- не запускает `winws.exe`, Zapret или WARP;
- не вызывает `warp-cli`;
- не выполняет `route add` или `route delete`;
- не меняет системные маршруты;
- не требует прав администратора;
- не использует `subprocess` для сетевого обхода.

Если FunPay доступен напрямую, `PROXY_URL` оставь пустым. Если сайт или Worker перестал открываться, можно указать обычный прокси:

```dotenv
PROXY_URL=http://логин:пароль@адрес:порт
```

Не публикуй этот адрес вместе с паролем.

## 11. Частые ошибки

### `.env` не найден

Создай его рядом с `main.py`:

```powershell
Copy-Item .env.example .env
```

Проверь, что Windows не добавила расширение `.txt`.

### `AI_WORKER_URL не задан`

Запусти Worker, скопируй его HTTPS-адрес и впиши его в `.env`. После изменения настроек перезапусти `py main.py --selftest`.

### Worker отклоняет токен

Значение `AI_WORKER_TOKEN` должно полностью совпадать с секретом `PROXY_TOKEN` на Worker'е. Удали лишние пробелы и повторно задеплой Worker.

### `no_binding` или `cloudflare: false`

В настройках Worker добавь Workers AI binding с именем ровно `AI`, затем сделай Deploy.

### `429 ai_limit_reached`

Бот сначала переходит к следующей модели из `AI_MODEL_PRIORITY`. Если весь список исчерпан, появляется `AILimitReached`, а главный цикл ждёт и продолжает позже. Проверь дневную квоту Cloudflare и наличие ключа Gemini, если он указан в цепочке.

### Gemini отвечает ошибкой региона

Это ограничение Google, аккаунта или региона выполнения Worker. Оставь Gemini запасным вариантом, проверь `colo` в `/health` и не отправляй в запросах секретные данные.

### Гайд не прошёл проверку

Это может произойти, если модель вернула отказ, слишком короткий текст, финальный вывод или слишком много буллитов. Бот попробует дополнительный запрос и другой промпт, а не будет публиковать явно плохой текст.

### FunPay недоступен

Открой `https://funpay.com` в браузере. Если сайт открывается, повтори `py main.py --selftest`. Если нет — настрой `PROXY_URL`. Для этого не нужны системные маршруты и права администратора.

### Google Drive не проходит проверку

Проверь:

- включён ли Google Drive API;
- лежит ли `client_secrets.json` рядом с `main.py`;
- разрешён ли доступ нужному Google-аккаунту;
- правильный ли `GOOGLE_DRIVE_FOLDER_ID`;
- не удалён ли `token.json` после первой авторизации.

### На FunPay слишком много предложений или лимит категории

Это ограничение самой категории. Бот фиксирует обработку и переходит к следующей игре, не создавая бесконечный поток публикаций.

## 13. Публикация изменений через GitHub

Рабочая ветка Arena фиксирована и не должна заменяться другой веткой:

```text
arena/01a0f1e0-rublyevky
```

Безопасный порядок:

1. проверить `git diff` и тесты;
2. сделать небольшой понятный коммит;
3. отправить только Arena-ветку;
4. открыть Pull Request в `main` кнопкой **Create PR**;
5. после проверки PR создать тег на принятом коммите `main`.

Не делай force-push в `main`, не удаляй `.git` и не выполняй команды, которые удаляют корень репозитория.
