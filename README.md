# FunPay Auto-Bot

Бот для подготовки и публикации цифровых товаров на FunPay. Он:

- берёт игры из `data/games_list.txt`;
- находит раздел игры на FunPay;
- генерирует идеи и подробные гайды через личный Cloudflare Worker;
- загружает гайды на Google Drive;
- создаёт и публикует лоты;
- ведёт логи, тайминги и расход токенов;
- подстраивает три обязательных товара под конкретную игру.

Текущая версия инструкции: **v19.12**.

> Важно: бот не запускает Zapret, WARP, `winws`, `warp-cli`, системные маршруты и команды от администратора. FunPay открывается напрямую, а при необходимости используется обычный прокси из `.env`.

## 1. Быстрый запуск

### Что нужно подготовить

- Windows;
- Python 3.10 или новее;
- аккаунт FunPay и Golden Key;
- Google Drive и OAuth Desktop app для Google Drive API;
- аккаунт Cloudflare;
- интернет, с которого открывается FunPay и адрес Worker'а.

### Команды PowerShell

Открой PowerShell и выполни команды из папки проекта:

```powershell
cd C:\путь\к\rublyevky
py -m pip install -r requirements.txt
Copy-Item .env.example .env
```

После этого заполни `.env`, настрой Google Drive и Cloudflare Worker по разделам ниже.

Сначала всегда запускай безопасную проверку:

```powershell
py main.py --selftest
```

`--selftest` ничего не публикует и не обрабатывает игры. Когда все обязательные пункты готовы, запускай бота:

```powershell
py main.py
```

Остановить работу можно сочетанием `Ctrl + C`.

## 2. Файл `.env`

Файл должен лежать рядом с `main.py` и называться именно `.env`, а не `.env.txt`.

Минимальная настройка:

```dotenv
GOLDEN_KEY=твой_golden_key_от_funpay
GOOGLE_DRIVE_FOLDER_ID=id_папки_google_drive
AI_WORKER_URL=https://имя-твоего-worker.workers.dev
AI_WORKER_TOKEN=секретный_пароль_worker
AI_MODEL_PRIORITY=gemini-3.6-flash
AI_TIMEOUT=180
```

### Что означает каждая строка

| Переменная | Обязательно | Назначение |
|---|---:|---|
| `GOLDEN_KEY` | да | Авторизация на FunPay. Берётся в настройках FunPay. |
| `GOOGLE_DRIVE_FOLDER_ID` | да | ID папки, куда бот загружает гайды. |
| `AI_WORKER_URL` | да | Адрес личного Cloudflare Worker без завершающего `/`. |
| `AI_WORKER_TOKEN` | да | Должен совпадать с секретом `PROXY_TOKEN` на Worker'е. |
| `AI_MODEL_PRIORITY` | нет | Рабочая модель. По умолчанию `gemini-3.6-flash`. |
| `AI_TIMEOUT` | нет | Таймаут одного запроса к ИИ в секундах. По умолчанию `180`. |
| `AI_ATTEMPTS` | нет | Число попыток одной модели. По умолчанию `2`. |
| `DEBUG_LOGS` | нет | `1` — показывать в консоли модели, тайминги, токены и уровни сокращения summary. |
| `PROXY_URL` | нет | Обычный HTTP-прокси только если FunPay или Worker не открываются напрямую. |
| `AI_PROXY_URL` | нет | Прокси только для запросов к Worker'у. Важнее `PROXY_URL`. Нужен, когда провайдер блокирует `*.workers.dev`, а FunPay открыт. |
| `GEMINI_API_KEY` | нет | Ключ Gemini из AI Studio. Бесплатный резерв: если Worker недоступен или заблокирован, бот спросит Gemini напрямую. |

Рабочий сценарий — одна модель Gemini через твой Worker:

```dotenv
AI_MODEL_PRIORITY=gemini-3.6-flash
```

Других моделей бот не вызывает: ни `@cf/qwen/qwen3-30b-a3b-fp8`, ни `@cf/openai/gpt-oss-120b`, ни `@cf/openai/gpt-oss-20b`, ни `g4f`. Если Gemini отвечает лимитом, бот не подменяет его другой моделью, а выдаёт понятную ошибку после исчерпания цепочки из одного элемента.

Секреты нельзя вписывать в `README.md`, `worker/wrangler.toml` или другие файлы, которые отправляются в Git. Файлы `.env`, `token.json`, `client_secrets.json` и локальные секреты Wrangler уже исключены через `.gitignore`.

## 3. Google Drive через OAuth Desktop app

Сервисный аккаунт для обычной настройки не нужен. Используй OAuth-клиент типа **Desktop app**.

### Подготовка Google Cloud

1. Открой [Google Cloud Console](https://console.cloud.google.com/).
2. Создай проект или выбери существующий.
3. Включи **Google Drive API**: `APIs & Services` → `Library` → `Google Drive API` → `Enable`.
4. Открой `APIs & Services` → `Credentials`.
5. Создай **OAuth client ID**.
6. В качестве типа приложения выбери **Desktop app**.
7. Скачай JSON-файл.
8. Переименуй его в `client_secrets.json` и положи рядом с `main.py`.
9. Если Google попросит настроить экран согласия, добавь свой Google-аккаунт в Test users.

### ID папки

1. Создай папку на Google Drive.
2. Открой её в браузере.
3. Скопируй часть адреса после `/folders/`:

```text
https://drive.google.com/drive/folders/1abcDEF_example
                                         └──────────────┘
```

4. Впиши эту часть в `.env`:

```dotenv
GOOGLE_DRIVE_FOLDER_ID=1abcDEF_example
```

При первом запуске `py main.py --selftest` откроется браузер для разрешения доступа. После авторизации появится `token.json`. Не удаляй его и не добавляй в Git.

## 4. Cloudflare Worker для ИИ

Бот использует HTTP-клиент `modules/ai_client.py` и обращается только к своему Worker'у. Рабочая модель — **Gemini** (`gemini-3.6-flash`). Gemini SDK в боте не используется: если нужен Gemini, Worker обращается к нему сам по HTTP, ключ лежит в секретах Worker'а. Запасного пути через `g4f` нет.

Схема:

```text
бот на Windows
    │ HTTPS + AI_WORKER_TOKEN
    ▼
твой Cloudflare Worker
    └── Gemini (секрет GEMINI_API_KEY на Worker'е)
```

### Вариант A: через веб-панель Cloudflare

1. Открой [Cloudflare](https://dash.cloudflare.com/sign-up) и создай аккаунт.
2. Открой `Workers & Pages` → `Create` → `Create Worker`.
3. Создай Worker, например с именем `ai-worker`.
4. Нажми `Edit code`.
5. Удали демонстрационный код и вставь содержимое файла `worker/worker.js`.
6. Нажми `Deploy`.
7. В настройках Worker открой `Settings` → `Variables and Secrets`.
8. Добавь секрет:
   - имя: `PROXY_TOKEN`;
   - значение: длинный пароль, придуманный тобой.
9. В `Settings` → `Bindings` добавь **Workers AI** с именем привязки ровно `AI`.
10. Снова выполни `Deploy`.
11. Скопируй адрес Worker'а вида `https://имя.workers.dev` в `.env`:

```dotenv
AI_WORKER_URL=https://имя.workers.dev
AI_WORKER_TOKEN=тот_же_пароль_что_и_PROXY_TOKEN
```

### Вариант B: через Wrangler

Node.js для этого варианта должен быть установлен. Выполняй команды из PowerShell:

```powershell
cd C:\путь\к\rublyevky\worker
npx --yes wrangler login
npx --yes wrangler deploy
npx --yes wrangler secret put PROXY_TOKEN
```

Команда `secret put` попросит ввести значение скрытого секрета. Не вставляй его в чат, README или Git.

После добавления или изменения кода Worker его нужно повторно задеплоить:

```powershell
cd C:\путь\к\rublyevky\worker
npx --yes wrangler deploy
```

Локальные секреты Wrangler можно хранить в `worker/.dev.vars`; этот файл уже исключён из Git.

### Проверка Worker

Открой в браузере:

```text
https://имя.workers.dev/health
```

В рабочем ответе должно быть примерно следующее:

```json
{
  "ok": true,
  "version": "1.1",
  "colo": "...",
  "providers": {
    "cloudflare": true,
    "gemini": false,
    "groq": false,
    "openrouter": false
  }
}
```

- `ok: true` — Worker отвечает;
- `cloudflare: true` — подключена привязка Workers AI;
- `gemini: true` — на Worker задан `GEMINI_API_KEY`;
- `colo` — дата-центр, в котором обработан запрос.

Если Worker задеплоен давно, он может не знать новые имена моделей: тогда самопроверка сообщит об этом отдельной строкой. Что делать — см. раздел [«Worker не знает модель»](#worker-не-знает-модель).

После этого проверь всю цепочку с компьютера:

```powershell
cd C:\путь\к\rublyevky
py main.py --selftest
```

### Свой домен вместо `workers.dev`

Cloudflare отвечает на один и тот же адрес Worker'а с нескольких anycast-IP, а провайдер в РФ режет часть этих адресов. DNS при этом может выдать именно заблокированные, и тогда Worker «то работает, то нет»: FunPay, Google Drive и `generativelanguage.googleapis.com` открываются, а Worker отдаёт `ConnectionResetError 10054` или таймаут.

Начиная с v19.12 бот сам перебирает адреса Cloudflare (включая DNS-over-HTTPS), выбирает рабочий и ходит через него — при старте и повторно, если адрес перестал отвечать. В `--selftest` это видно строкой `• рабочий адрес Cloudflare: ...`. Ничего настраивать не нужно.

Если не отвечает ни один адрес, проверь это вручную:

```powershell
curl.exe -4 -o NUL -w "worker: %{http_code}`n" --max-time 10 https://имя-твоего-worker.workers.dev/health
nslookup имя-твоего-worker.workers.dev 1.1.1.1
```

Если `000` — волна блокировки. Она обычно проходит за несколько минут, бот подождёт и продолжит. Постоянное решение — свой домен: он бесплатно привязывается к тому же Worker'у, код бота и `worker.js` менять не нужно.

1. Купи домен у любого регистратора (подойдёт самый дешёвый, например `.ru`).
2. В [Cloudflare Dashboard](https://dash.cloudflare.com) нажми **Add a site**, введи домен, выбери план **Free**.
3. Cloudflare покажет два своих NS-сервера. Пропиши их у регистратора вместо старых и дождись письма «сайт активен» (от нескольких минут до нескольких часов).
4. Открой **Workers & Pages → твой Worker → Settings → Domains & Routes → Add → Custom domain**.
5. Введи поддомен, например `ai.твой-домен.ru`, и нажми **Add domain**. Cloudflare сам создаст DNS-запись и выпустит сертификат (обычно за минуту).
6. В `.env` замени адрес Worker'а:

   ```dotenv
   AI_WORKER_URL=https://ai.твой-домен.ru
   ```

   Слэш на конце не нужен. `AI_WORKER_TOKEN` остаётся прежним, Worker передеплоивать не нужно.
7. Проверь:

   ```powershell
   curl.exe -4 https://ai.твой-домен.ru/health
   py main.py --selftest
   ```

   В `/health` должен быть тот же JSON с `"version": "1.1"` и `"gemini": true`.

Бери поддомен (`ai.`), а не сам домен: на apex-домене Cloudflare иногда конфликтует с существующими записями. Запись должна оставаться в режиме «Proxied» (оранжевая cloud) — Custom Domain включает его сам.

Если домена нет и покупать не хочется, есть бесплатный путь — прямой Gemini API, без Worker'а вообще.

### Бесплатный обход: прямой Gemini API

У бота есть резервный режим: если Worker недоступен (заблокирован, лежит, отдаёт обрыв), бот сам переключается на `generativelanguage.googleapis.com` — этот адрес в РФ не блокируется. Нужен только ключ Gemini в `.env`:

1. Открой [aistudio.google.com/apikey](https://aistudio.google.com/apikey) и создай ключ (**Create API key**). Это бесплатно, карта не нужна.
2. Впиши его в `.env`:

   ```dotenv
   GEMINI_API_KEY=твой_ключ
   ```

3. Проверь:

   ```powershell
   py main.py --selftest
   ```

   Строка `GEMINI_API_KEY` станет ✅. Если Worker при этом не отвечает, самопроверка напишет, что запросы пойдут напрямую, и тестовый текст всё равно сгенерируется.

Ключ можно взять тот же, что лежит в секретах Worker'а (`GEMINI_API_KEY` в Cloudflare → Settings → Variables and Secrets): тогда ничего создавать заново не нужно.

Как это работает:

- бот сначала пробует Worker, как раньше;
- при сетевом обрыве или таймауте один раз спрашивает Gemini напрямую;
- расход по-прежнему пишется в `logs/ai_usage.jsonl`, но счётчик запросов внутри Worker'а не увеличивается.

Ограничение: у бесплатного тарифа Gemini есть суточная квота на модель. Если она кончится, бот получит `429` и напишет об этом — тогда ждите сброса или включайте платный тариф в AI Studio.

`AI_PROXY_URL` (см. раздел 9) остаётся третьим вариантом: прокси только для запросов к Worker'у, FunPay продолжает работать напрямую.

### Секрет Gemini и региональные ограничения

Gemini — единственная рабочая модель. Её секрет добавляется на Worker, а не в `.env` бота:

```powershell
cd C:\путь\к\rublyevky\worker
npx --yes wrangler secret put GEMINI_API_KEY
npx --yes wrangler deploy
```

В текущем Worker поддерживаются следующие имена Gemini:

```text
gemini-3.8-flash
gemini-3.7-flash
gemini-3.6-flash
gemini-3.5-flash
gemini-3.5-flash-lite
gemini-3.1-flash-lite
```

Рабочий пример — одна модель:

```dotenv
AI_MODEL_PRIORITY=gemini-3.6-flash
```

У Gemini могут быть ограничения по стране, аккаунту, бесплатной квоте и доступности конкретной модели. Даже если ключ создан, Google может вернуть ошибку региона или лимита. Поскольку других моделей в цепочке нет, бот не подменяет Gemini другой моделью: при ответе `429` он выдаёт понятную ошибку `AILimitReached` с именем модели, а главный цикл ждёт сброса лимита и продолжает с того же места.

Запросы к Gemini могут использоваться Google для улучшения сервиса согласно настройкам аккаунта и тарифа. Не отправляй через Gemini ключи, пароли, персональные данные и содержимое `.env`.

### Другие запасные провайдеры

Worker дополнительно умеет работать с Groq и OpenRouter. Их ключи добавляются только как секреты Worker'а:

```powershell
cd C:\путь\к\rublyevky\worker
npx --yes wrangler secret put GROQ_API_KEY
npx --yes wrangler secret put OPENROUTER_API_KEY
npx --yes wrangler deploy
```

Эти провайдеры не входят в рабочий сценарий. Модели других провайдеров можно вписать в `AI_MODEL_PRIORITY` только осознанно и после проверки их доступности и лимитов — бот будет звать ровно то, что указано в этой строке.

## 5. Список игр и первый запуск

Список игр находится в:

```text
data/games_list.txt
```

Пиши по одной игре на строку:

```text
Cyberpunk 2077
Hogwarts Legacy
Valheim
```

Перед первым запуском сделай резервную копию списка:

```powershell
Copy-Item data\games_list.txt data\games_list_backup.txt
```

После успешной обработки бот удаляет игру из `data/games_list.txt` и переходит к следующей. Файл `data/processed_games.json` используется для защиты от повторной публикации и не должен редактироваться вручную.

Если FunPay не ответил (таймаут, Cloudflare, ошибка статуса) или подвёл ИИ, игра **остаётся** в списке: бот пишет причину и повторяет её в следующем круге. Из списка игра исчезает только после успешной публикации, если её действительно нет на FunPay, или если она уже обрабатывалась.

### Самопроверка

```powershell
py main.py --selftest
```

Проверяются:

1. наличие `.env` и основных переменных;
2. доступность Worker и его `/health`;
3. тестовый ответ ИИ;
4. доступность FunPay и авторизация по `GOLDEN_KEY`;
5. Google Drive и возможность создать временную папку;
6. накопленный расход запросов и токенов за текущий день.

Самопроверка не публикует лоты и не удаляет игру из списка.

### Рабочий запуск

```powershell
py main.py
```

Для каждой игры бот:

1. находит категорию FunPay;
2. генерирует до 12 обычных идей;
3. проверяет три обязательных товара под игру;
4. получает ровно три обязательных товара — исходных или адаптированных;
5. создаёт до 15 гайдов;
6. загружает файлы в папку Google Drive;
7. публикует обычные лоты за 1 рубль;
8. при наличии игры в `data/wemod_games_list.txt` отдельно обрабатывает WeMod-лот за 60 рублей;
9. отмечает игру обработанной и удаляет её из входного списка.

## 6. Обязательные товары и адаптация под игру

Базовый список находится в `config.py` в переменной `MANDATORY_PRODUCTS`. У каждого товара есть устойчивый `id`:

- `pc_optimization`;
- `ping`;
- `hwid`.

Название, тип и `content_points` можно редактировать в `config.py`. Поля `id` не переименовывай: по ним сопоставляется ответ ИИ.

Проверка работает в два этапа:

1. быстрый локальный фильтр смотрит на название игры и раздел FunPay;
2. если ситуация неочевидна, один JSON-запрос ИИ оценивает все три товара сразу.

Для явно мобильной, консольной или офлайн-игры запрос к ИИ для очевидных замен не тратится. Неподходящие темы заменяются обычными игровыми идеями. Причина каждой замены попадает в:

```text
logs/mandatory_products.jsonl
```

В результате сохраняется схема:

```text
3 адаптированных обязательных товара + до 12 обычных идей = до 15 товаров
```

## 7. Тексты, summary и описания лотов

### Summary

Заголовок короткого описания укладывается одновременно в ограничения FunPay:

- от 10 до 70 символов;
- не больше 120 UTF-8 байт.

Оба лимита проверяются одновременно: `len(text)` и `len(text.encode("utf-8"))`.

Сокращение выполняется осознанно:

1. убирается бонус;
2. убирается упоминание авто-выдачи;
3. сокращается название целыми словами;
4. только затем выбирается безопасный вариант из целых слов.

Строка не режется по символам и не режется по байтам, поэтому эмодзи-кластеры и
`U+FE0F` не рвутся. Из всех вариантов выбирается **самый длинный**, который проходит
оба лимита, а не первый подошедший. После сокращения проверяется, что строка не
заканчивается на открывающей скобке, дефисе, одиночном variation selector или
оборванной декоративной конструкции и что в ней не осталось незакрытых скобок.
Часть оформления шаблона сохраняется, если она помещается. Уровень сокращения
пишется только в `logs/errors.log` — в обычной консоли этого сообщения нет.

### Полное описание

В полном русском описании явно остаётся одна строка `АВТОВЫДАЧА 24/7`. Текст вокруг неё варьируется: описания не состоят из одной копии с повторяющимися рекламными фразами.

### ИИ-гайды

Промпты требуют:

- начать сразу с конкретного действия или настройки (для оптимизации ПК — настройки игры, Windows, драйвера или видеокарты);
- прямую связь с названием игры, названием товара и `content_points`;
- конкретные игровые детали: предметы, локации, режимы, механики, числа и условия;
- обычные абзацы разной длины;
- редкие списки только там, где они полезны;
- отсутствие `##`, мета-вступлений, выводов и рядов декоративных эмодзи.

Перед проверкой качества бот удаляет запрещённые мета-фразы, финальные секции «Итоги»/«Выводы», Markdown-заголовки и подряд идущие эмодзи. Текст, в котором больше примерно 40% непустых строк являются пунктами списка, отбраковывается.

Дополнительно работает пост-проверка качества:

- наличие названия игры или его нормальной формы;
- наличие нескольких ключевых слов из `title` и `content_points`;
- отбраковка художественного вступления («Представь, что ты…», деревни, леса, силуэты);
- отбраковка общего текста без связи с игрой;
- отбраковка текста с повторами одной мысли разными словами;
- минимальная длина и доля строк-буллитов.

После плохого ответа бот делает дополнительные попытки, включая самую строгую. Плохой гайд не публикуется: товар пропускается.

Гайд запрашивается двумя короткими частями (примерно 450–550 и 300–400 слов), а не одним длинным ответом: длинная генерация идёт дольше минуты, и соединение с Worker'ом успевает оборваться по таймауту. Если Worker или провайдер недоступен, бот не тратит четыре попытки на разные промпты, а пишет причину, оставляет игру в списке и ждёт 60 секунд.

Если гайд оказался короче требуемого объёма, бот один раз просит дописать его. Текст длиннее 500 символов после дополнительной попытки может быть принят, если он не похож на отказ или список.

## 8. Ускорение и логи ИИ

Идеи начинают генерироваться параллельно с поиском раздела игры. При обработке товаров заранее готовится только следующий гайд; используется осторожный пул максимум из двух задач, поэтому бот не создаёт очередь из десятков запросов.

В обычной консоли остаётся только короткий итог по каждому товару:

```text
[7/15] ✅ УСПЕШНО ВЫСТАВЛЕНО!
[8/15] ❌ НЕ ВЫСТАВЛЕНО: сетевая ошибка
```

Название игры, раздел FunPay, ошибки публикации и сетевые подсказки тоже видны.
Если лот реально не выставился, строка «УСПЕШНО» не печатается.

Пока идёт генерация и публикация, консоль не молчит: сначала печатается
`⏳ Считаем гайды и публикуем лоты...`, а если один гайд считается дольше
45 секунд — раз в 45 секунд добавляется строка `⏳ Гайд ещё считается (N с)...`.
Это не технический лог, а только признак того, что бот жив: без него долгий
запрос к ИИ выглядит как зависание.

Подробный режим включается переменной окружения:

```powershell
$env:DEBUG_LOGS = "1"
py main.py
```

В нём в консоли дополнительно появляются:

- выбранная модель, время ответа и объём ответа ИИ;
- «попытка 1/2» и этапы генерации гайдов;
- «summary shortened» с уровнем сокращения;
- время генерации идей, гайдов, публикации и всей игры;
- количество запросов и токенов за игру.

Без `DEBUG_LOGS` всё это пишется только в файлы:

```text
logs/ai_usage.jsonl              расход запросов, тайминги и токены
logs/errors.log                  технические INFO и причины ошибок
logs/mandatory_products.jsonl    причины замен обязательных товаров
```

Логи не нужно добавлять в Git.

## 9. Сетевой слой и безопасность

Сетевой слой делает только следующее:

- создаёт обычную `requests.Session`;
- проверяет доступность FunPay;
- использует `PROXY_URL`, если он задан;
- пересоздаёт сессию при сетевом обрыве.

Он не делает следующего:

- не запускает `winws.exe`, Zapret или WARP;
- не вызывает `warp-cli`;
- не выполняет `route add` или `route delete`;
- не меняет системные маршруты;
- не требует прав администратора;
- не использует `subprocess` для сетевого обхода.

Если FunPay доступен напрямую, `PROXY_URL` оставь пустым. Если сайт или Worker перестал открываться, можно указать обычный прокси:

```dotenv
PROXY_URL=http://логин:пароль@адрес:порт
```

Провайдеры в РФ режут часть anycast-адресов Cloudflare, а DNS может выдать именно недоступные — тогда Worker «то работает, то нет». С v19.12 бот сам находит рабочий адрес и переключается на него, так что обычно достаточно просто запустить снова. Если не помогло ни один адрес:

1. **Свой домен для Worker'а.** В Cloudflare: Workers & Pages → твой Worker → Settings → Domains & Routes → Add → Custom domain. После привязки домена (например, `ai.example.ru`) поставь `AI_WORKER_URL=https://ai.example.ru`. Код менять не нужно.
2. **Прокси только для ИИ.** В `.env`:
   ```dotenv
   AI_PROXY_URL=http://логин:пароль@адрес:порт
   ```
   Он важнее `PROXY_URL` и применяется только к запросам к Worker'у, FunPay продолжает работать напрямую.
3. **Прямой Gemini API без Worker'а.** `GEMINI_API_KEY=...` в `.env` — бесплатно, ничего покупать не нужно. Подробности — раздел 4, «Бесплатный обход: прямой Gemini API».

Не публикуй эти адреса вместе с паролем.

## 11. Частые ошибки

### `.env` не найден

Создай его рядом с `main.py`:

```powershell
Copy-Item .env.example .env
```

Проверь, что Windows не добавила расширение `.txt`.

### `AI_WORKER_URL не задан`

Запусти Worker, скопируй его HTTPS-адрес и впиши его в `.env`. После изменения настроек перезапусти `py main.py --selftest`.

### Worker отклоняет токен

Значение `AI_WORKER_TOKEN` должно полностью совпадать с секретом `PROXY_TOKEN` на Worker'е. Удали лишние пробелы и повторно задеплой Worker.

### `no_binding` или `cloudflare: false`

В настройках Worker добавь Workers AI binding с именем ровно `AI`, затем сделай Deploy.

### Worker не знает модель

Самопроверка или запуск пишет:

```text
[!] Worker не знает модель(и): gemini-3.6-flash
Доступные у Worker'а: gemini-2.5-flash, gemini-2.5-pro, gemini-2.0-flash
```

Причина — на Cloudflare крутится старая сборка Worker'а, которая знает только прежние имена моделей. `gemini-3.6-flash` — рабочая модель (есть в документации Google), менять её не нужно. Обнови сборку из этого репозитория:

```powershell
cd C:\путь\к\rublyevky\worker
npx --yes wrangler deploy
```

После деплоя версия в `/health` должна стать не ниже `1.1`, а `gemini-3.6-flash` появится в списке моделей. Проверь:

```powershell
curl https://имя-твоего-worker.workers.dev/v1/models
```

Как выйти из ситуации быстро, не трогая Worker: вписать в `.env` старую модель, которую Worker ещё помнит — `AI_MODEL_PRIORITY=gemini-2.5-flash`. Это временное решение: такие модели Google выводит из эксплуатации, поэтому основной вариант — обновление Worker'а.

Пока Worker не знает модель, бот не публикует лоты и не удаляет игры из списка: он ждёт 5 минут и проверяет снова. Так сбой ИИ не съедает `data/games_list.txt`.

### `ConnectionResetError 10054` или таймаут до Worker'а

Самопроверка пишет `сетевая ошибка: ('Connection aborted.', ConnectionResetError(10054, ...))` или просто не дожидается ответа. Токен и модель тут не при чём: до Worker'а не доходит соединение.

Обычно это значит, что провайдер режет адреса Cloudflare, которые выдал DNS. Бот с v19.12 перебирает адреса сам (в том числе через DNS-over-HTTPS) и переключается на рабочий — в `--selftest` появится строка `• рабочий адрес Cloudflare: ...`.

Если не отвечает ни один адрес:

1. **Подождать.** Такие волны проходят за несколько минут; бот сам повторит и не потеряет игры.
2. **Бесплатно:** добавить `GEMINI_API_KEY` в `.env` — бот пойдёт в Gemini напрямую, минуя Worker (раздел [«Бесплатный обход: прямой Gemini API»](#бесплатный-обход-прямой-gemini-api)).
3. Свой домен для Worker'а — раздел [«Свой домен вместо `workers.dev`»](#свой-домен-вместо-workersdev).
4. `AI_PROXY_URL` в `.env` — если есть рабочий прокси (раздел 9).

Пока Worker недоступен и ключа Gemini нет, бот не удаляет игры из списка: пишет причину и ждёт 60 секунд.

### `429 ai_limit_reached`

В рабочем сценарии модель одна — Gemini. Бот не подменяет её другой моделью: после ответа `429` он выдаёт понятную ошибку `AILimitReached` с именем модели, а главный цикл ждёт 30 минут и продолжает с того же места. Проверь секрет `GEMINI_API_KEY` на Worker'е и квоту Gemini.

### Gemini отвечает ошибкой региона

Это ограничение Google, аккаунта или региона выполнения Worker. Проверь `colo` в `/health`, при необходимости смени аккаунт или ключ Gemini и не отправляй в запросах секретные данные.

### Гайд не прошёл проверку

Это может произойти, если модель вернула отказ, слишком короткий текст, финальный вывод или слишком много буллитов. Бот попробует дополнительный запрос и другой промпт, а не будет публиковать явно плохой текст.

### FunPay недоступен

Открой `https://funpay.com` в браузере. Если сайт открывается, повтори `py main.py --selftest`. Если нет — настрой `PROXY_URL`. Для этого не нужны системные маршруты и права администратора.

### Google Drive не проходит проверку

Проверь:

- включён ли Google Drive API;
- лежит ли `client_secrets.json` рядом с `main.py`;
- разрешён ли доступ нужному Google-аккаунту;
- правильный ли `GOOGLE_DRIVE_FOLDER_ID`;
- не удалён ли `token.json` после первой авторизации.

### На FunPay слишком много предложений или лимит категории

Это ограничение самой категории. Бот фиксирует обработку и переходит к следующей игре, не создавая бесконечный поток публикаций.

## 13. Публикация изменений через GitHub

Рабочая ветка Arena фиксирована и не должна заменяться другой веткой:

```text
arena/ff4ba21b-rublyevky
```

Безопасный порядок:

1. проверить `git diff` и тесты;
2. сделать небольшой понятный коммит;
3. отправить только Arena-ветку;
4. открыть Pull Request в `main` кнопкой **Create PR**;
5. после проверки PR создать тег на принятом коммите `main`.

Не делай force-push в `main`, не удаляй `.git` и не выполняй команды, которые удаляют корень репозитория.
